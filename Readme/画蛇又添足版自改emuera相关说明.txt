	         OnPaint 内部访问 null 的 GRContext 导致未捕获的 NullReferenceException，程序直接崩溃。
	根本原因：
		1. SKGLControl.OnPaint 在 OpenGL 上下文未就绪时，内部 GRContext 为 null，后续操作抛出 NullReferenceException。
		2. 双显卡笔记本（如 Intel 集显 + AMD 独显）的 GPU 切换、驱动重置、锁屏恢复等场景会导致 OpenGL 上下文丢失。
		3. 原 CheckOpenGLCompatibility() 仅在启动时检测一次，无法应对运行时上下文丢失。
	修复方案：
		1. EraPictureBox.cs：重写 OnPaint()，用 try-catch 捕获 NullReferenceException，捕获后设置 UseOpenGL = false 并触发 OnOpenGLFailure 事件。
		2. MainWindow.cs：新增 SwapToSoftwareRendering() 方法，将 SKGLControl 替换为 SKControl（CPU 渲染），重新绑定鼠标事件和 PaintSurface。
		3. MainWindow.cs：新增 HandleOpenGLFailure() 订阅 OnOpenGLFailure 事件，线程安全地调用 SwapToSoftwareRendering()。
		4. MainWindow.cs：RenderConsole() 增加 try-catch 保护，当 console.OnPaint 抛出 NullReferenceException 时自动降级。
		5. MainWindow.cs：CheckOpenGLCompatibility() 重构，启动时检测失败也复用 SwapToSoftwareRendering()，消除重复代码。
	效果：OpenGL 不可用时自动无缝降级到 CPU 软件渲染，玩家无感知，不再崩溃。

修复 SpriteG 快照模式导致合成精灵渲染为空白的Bug：
	问题描述：SPRITECREATE 从 GraphicsImage 创建精灵时，旧版快照模式会在创建瞬间复制一份位图。如果此时 GraphicsImage 尚未绘制完成（如先 SPRITECREATE 再 GDRAWSPRITE），精灵捕获的是空白画布，导致后续渲染为透明。

	修复方案：移除快照模式，恢复引用模式。

修复彩色文字渲染偏细问题：
	问题描述：SETCOLOR 后 PRINT 的彩色文字视觉上比黑白文字偏细、偏虚，尤其红色/蓝色等低通道覆盖颜色最为明显。
	根本原因：
		1. Skia 管线中 SKPaint 设置了 SrcIn ColorFilter，将子像素抗锯齿（Subpixel AA）降级为灰度抗锯齿。彩色文字本身只有部分通道有覆盖信息，降级后精度损失更严重。
		2. GDI 管线中 CreateSkBitmapFromGdiBitmap 将 GDI+ 的 Straight Alpha 像素直接拷贝到 Skia 的 Premultiplied Alpha SKBitmap，未做预乘转换，导致半透明边缘像素 RGB 偏高。
		3. GDI 渲染分支在透明背景 Bitmap 上使用 ClearTypeGridFit，ClearType 依赖不透明背景进行子像素混合，透明背景上会产生黑晕。

	1. 修复 ConsoleStyledString.cs：
		- DrawTo() 和 DrawToBitmap() 中移除 SKPaint 的 SrcIn ColorFilter（paint.Color 已足够设置文字颜色，ColorFilter 多余且有害）
		- CreateSkBitmapFromGdiBitmap() 中添加 Straight Alpha → Premultiplied Alpha 逐像素转换，跳过 alpha=0 和 alpha=255 的像素以优化性能
		- 修正 unsafe 像素拷贝变量名：Format32bppArgb 内存顺序为 B,G,R,A，将 r/b 变量名修正为实际对应的 b/r
		- GDI 渲染分支 TextRenderingHint 从 ClearTypeGridFit 改为：光栅字体用 SingleBitPerPixelGridFit（原汁原味像素风），非光栅字体用 AntiAliasGridFit（避免透明背景上的 ClearType 黑晕）

EXISTVAR:
==================================
原版：

输入：string
返回：int
注释：

如果存在与 varName 同名的变量 / 常量则返回对应的正整数，否则返回 0。

为整数类型时，返回值 setbit 1
为字符串类型时，返回值 setbit 2
为常量类型时，返回值 setbit 3
为二维数组时，返回值 setbit 4
为三维数组时，返回值 setbit 5

命令 / 行内函数两种写法均有效。

改造：

输入：string,(int)
返回：int
注释：

如果存在第二输入变量，则将string所输入的变量视为一个具体的存储单元，判断是否存在，若存在返回1，不存在返回0

命令 / 行内函数两种写法均有效。

==================================
GETSOUNDORBGMINFO(新增):
==================================

读取SOUND通道或BGM通道的音频播放状态

输入：int, int(可省略)
返回：int
注释：

第一参数读取SOUND通道，第二参数读取所需的音频信息
音频信息总共有五种：音频总长度、当前播放进度、正在播放中、音频音量、音频速度
若第二参数存在，则1返回音频总长度、2返回当前播放进度、3返回正在播放中、4返回音频音量、5返回音频速度
返回值位于result:0中
若第二参数不存在，则同时返回所有信息，result:0返回音频总长度、result:1返回当前播放进度、result:2返回正在播放中、result:3返回音频音量、result:4返回音频速度

命令 / 行内函数两种写法均有效。

==================================
ISPLAYINGSOUND(新增):
==================================

判断SOUND通道是否正在播放

输入：int（可省略）
返回：int
注释：

输入一个参数以检查某个通道是否有音频正在播放，若正在播放，则返回通道编号，否则返回-1
省略参数的情况下将遍历所有通道，直到检测到正在播放的通道时返回通道编号，或者遍历完所有通道后返回-1

命令 / 行内函数两种写法均有效。

==================================
SOUNDCONTROL(新增):
==================================

控制SOUND通道的音频播放情况

输入：  ① int, int
		② int, int, int, int（可省略）
返回：int
注释：

情况①：第一参数为通道编号，第二参数为控制类型
控制类型总共有两种种：0为暂停，1为继续播放，2为停止

情况②：第一参数为通道编号，第二参数为变速操控编号（仅支持3），第三参数为变速倍率，第四参数为变速类型
若第四参数存在，则变速时音调会随速度改变
若不存在，这变速时音调不改变

以上两种情况下，若通道编号不存在，返回-1，若控制类型不存在，返回-2，若控制成功，返回1

命令 / 行内函数两种写法均有效。
